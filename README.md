# My Polyphony

一人で「自分」と「相手」の二つの声を書き分けながら、考えを対話篇として整理するブラウザアプリです。

対話の内容は外部へ送信されず、現在使っているブラウザの `localStorage` にだけ自動保存されます。過去作はJSONとして書き出し、あとから読み込んで続きを編集できます。TXTは文章として読むための書き出し形式です。

## 主な使い方

1. 入力欄に最初の発言を書きます。最初の話者は「自分」です。
2. 文書表示では `Enter`、チャット表示では「送る」で発言を確定します。
3. 発言を確定するたびに「自分」と「相手」が自動で交替します。
4. 同じ話者を続ける場合は、`Ctrl + Alt + M` で次の話者を切り替えます。
5. 確定済みの発言は「編集」「削除」から修正できます。
6. 「設定」から、対話篇の読み込み、復元用JSONまたは閲覧用TXTの書き出し、書体の変更ができます。

`Ctrl + Alt + M` による話者切替は、文書表示とチャット表示のどちらでも利用できます。切替後に発言を確定すると、通常どおり次の話者へ自動交替します。

文書表示で同じ発言内を改行する場合は `Shift + Enter` を使います。チャット表示は通常の `Enter` で改行でき、`Ctrl + Enter` または `⌘ + Enter` でも送信できます。

スマートフォンのチャット表示では、上部の `⛶` ボタンからチャットを全画面表示にできます。全画面中は同じ位置の `×` ボタン、またはブラウザ標準の終了操作で元の表示へ戻れます。

書体は、現在の明朝体、ゴシック体、`Noto Sans JP`を優先するゴシック体から選べます。選択した書体は現在のブラウザに保存され、次にMyPolyphonyを開いたときにも引き継がれます。`Noto Sans JP`が端末にない場合は、端末で利用できるゴシック体を使います。

## ローカルで開く

`index.html` をダブルクリックすれば、そのままブラウザで利用できます。サーバーやインストールは不要です。配布用の `index.html` にはJavaScriptとCSSが埋め込まれているため、このファイル一つだけで動作します。

開発・確認用にローカルサーバーから開く場合は、Node.jsがあれば次を実行します。

```sh
npx serve .
```

Pythonがある場合：

```sh
python -m http.server 4173
```

後者の場合は、ブラウザで `http://localhost:4173/` を開きます。

## 文書表示の文字と間隔を調整する

`index.html` の先頭付近にある `my-polyphony-local-tuning` という表示調整欄では、文書表示の密度を数値で変更できます。この欄は自動生成の対象外であるため、開発用ファイルから `index.html` を更新しても指定値が保たれます。

```css
:root {
  --desktop-message-gap: 0.8rem;
  --desktop-self-to-self-gap: 0.8rem;
  --desktop-message-padding-block: 0.8rem;
  --desktop-message-min-height: 3.3rem;
  --desktop-content-font-size: clamp(1rem, 1.7vw, 1.17rem);
  --desktop-content-line-height: 2;
}
```

たとえば、連続する「自分」の発言を詰め、本文も小さくする場合は次の値から試せます。

```css
--desktop-message-gap: 0.35rem;
--desktop-self-to-self-gap: 0.15rem;
--desktop-message-padding-block: 0.35rem;
--desktop-message-min-height: 0rem;
--desktop-content-font-size: clamp(0.92rem, 1.3vw, 1.05rem);
--desktop-content-line-height: 1.6;
```

`line-height: 1.6` は、一行の高さを文字サイズの1.6倍にする指定です。`clamp(最小値, 画面幅に応じた値, 最大値)` は、画面の幅に応じて文字サイズをその範囲内で変化させます。値を保存してブラウザを再読み込みすると結果を確認できます。

## 開発時の構成

開発では、役割ごとのファイルを編集元として扱います。

- `model.js`: 発言、下書き、読み書き形式など、対話篇そのものの規則
- `preferences.js`: 書体と表示モードの設定値
- `storage.js`: ブラウザ内保存との境界
- `view.js`: DOM要素の取得、発言要素の生成、表示用の整形
- `interaction.js`: 発言後の話者、確定キー、話者切替キーなど、交換可能な操作方針
- `editors.js`: 文書表示とチャット表示それぞれの入力イベントの接続
- `viewport.js`: 入力位置へのフォーカスと、表示ごとに交換可能な画面追従方針
- `app.js`: 採用する操作方針を選び、各役割を結び付ける画面操作の進行
- `styles.css`: 色、寸法、文書表示、チャット表示を含む基本スタイル

発言の追加、話者交代、キー操作は別々の規則として扱います。すなわち、自動交代と手動交代を比較するときにも、保存形式や発言データを変更せず、`interaction.js` の方針と対応するテストを交換できます。文書表示とチャット表示はそれぞれ別の方針を選べるため、片方だけで操作を試すこともできます。

画面追従も同様に、現在位置を保つ方式、チャット末尾へ移動する方式、入力位置が画面下端を越えた分だけページを送る方式を分けています。現在の見た目と動作を維持するため、文書表示では現在位置を保つ方針を選択しています。

編集後は次を実行すると、これらの内容が `index.html` へ埋め込まれます。

```sh
npm run build
```

すなわち、実装は役割別のファイルで読みやすく保ち、利用時には従来どおり単一HTMLを使う構成です。

## テスト

追加パッケージのインストールは不要です。Node.js 20以降で次を実行します。

```sh
npm test
```

構文チェックを含める場合：

```sh
npm run check
```

`npm run check` は構文、動作テスト、`index.html` と編集元の同期を確認します。

## GitHub Pagesで公開する

1. このフォルダーをGitHubリポジトリの既定ブランチへpushします。
2. GitHubのリポジトリ画面で **Settings → Pages** を開きます。
3. **Build and deployment** のSourceを **Deploy from a branch** にします。
4. 既定ブランチと **/ (root)** を選び、保存します。

すべてのアセットを相対パスで参照しているため、`https://ユーザー名.github.io/リポジトリ名/` のようなサブパスでも動作します。

## JSON形式

```json
{
  "format": "my-polyphony-dialogue",
  "version": 1,
  "exportedAt": "2026-08-06T12:00:00.000Z",
  "messages": [
    { "role": "self", "text": "自分の発言" },
    { "role": "other", "text": "相手の発言" }
  ]
}
```

`role` は `self` または `other` です。TXTからの読み込みには対応していません。

## プライバシーと保存範囲

- サーバー、外部API、アクセス解析は使用していません。
- 保存内容はブラウザと端末ごとに独立しています。
- 書体の設定は対話篇と別に保存されるため、JSONには含まれず、JSONの読み込みや「新しく始める」の後にも維持されます。
- ブラウザのサイトデータを消去すると自動保存分も消えるため、大切な対話篇はJSONで書き出してください。

## MVPに含まれないもの

音声入力、三者以上の会話、画面上の操作による文字色や文字サイズのカスタマイズ、クラウド同期、共同編集、TXT読み込みには対応していません。文書表示の文字サイズと間隔は、上記の表示調整欄から変更できます。
